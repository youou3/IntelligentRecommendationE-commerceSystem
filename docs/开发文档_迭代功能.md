# 中小型智能电商 SaaS 系统迭代开发文档

## 1. 文档目标

本文档用于指导系统按阶段迭代落地，重点围绕“行为采集 -> 用户画像 -> 推荐 -> 选品 -> 库存预警 -> 自动补货 -> 运营复盘”建立可执行闭环。

目标不是一次性完成全部能力，而是优先交付可验证、可追踪、可扩展的最小闭环，再逐步增强算法、流程和运营能力。

## 2. 里程碑规划

### 第一阶段：数据与基础闭环

目标：先打通最小可用链路，保证数据能进入系统并形成基础画像和推荐输出。相关架构、接口和数据库约束见 [开发文档_架构接口与多租户预留.md](开发文档_架构接口与多租户预留.md) 与 [docs/README.md](README.md)。

交付内容：

- 搭建 Flask 项目基础结构。
- 完成 MySQL、MongoDB 连接与基础配置。
- 建立用户、商品、订单、库存核心模型。
- 实现用户行为采集接口。
- 实现行为日志写入 MongoDB。
- 实现关键业务事件的结构化落库。
- 实现基础用户画像生成。
- 实现标签匹配推荐接口。
- 记录推荐曝光、点击、加购等反馈数据。

验收标准：

- 用户行为能够稳定采集并写入系统。
- 能根据行为数据生成基础用户画像。
- 能返回可解释的个性化推荐结果。
- 推荐反馈能够回流并被后续任务读取。

### 第二阶段：推荐与选品增强

目标：让推荐和选品具备实际业务可用性，而不是仅有基础输出。

交付内容：

- 实现商品标签向量化。
- 实现用户标签权重更新机制。
- 实现余弦相似度推荐算法。
- 实现推荐业务过滤策略，包括库存、状态、去重、频控。
- 实现智能选品评分模型。
- 实现商品分层与运营建议输出。
- 补充新用户、新商品的冷启动策略。

验收标准：

- 推荐结果可解释、可复盘。
- 商品可按爆品、潜力品、长尾品、风险品分层。
- 推荐点击、加购、购买数据可用于分析。
- 新用户和新商品都有兜底推荐策略。

### 第三阶段：库存与补货工作流

目标：打通库存自动化流程，形成可执行的库存预警和补货闭环。

交付内容：

- 实现库存预警 SKILL。
- 实现补货建议 SKILL。
- 实现库存预警 WORKFLOW。
- 实现自动补货 WORKFLOW。
- 实现补货单生成与状态流转。
- 实现商家后台库存预警列表。
- 处理库存变更、退款回滚、锁定库存释放等事件。

验收标准：

- 系统能自动识别库存风险。
- 系统能生成补货建议或清仓建议。
- 补货流程有完整状态记录。
- 入库结果能反哺库存和选品模型。

### 第四阶段：MCP / SKILL 标准化

目标：提升系统扩展能力，降低新增能力对主流程的侵入。

交付内容：

- 实现 MCP 注册中心。
- 统一 SKILL 输入输出协议。
- 增加 SKILL 调用日志与耗时统计。
- 增加 SKILL 异常降级机制。
- 将推荐、选品、库存、补货能力统一改造为 SKILL。
- WORKFLOW 统一通过 MCP 调用能力。

验收标准：

- 新增 SKILL 不需要修改主业务流程。
- WORKFLOW 可以稳定编排多个 SKILL。
- 每次能力调用都可追踪、可监控、可复盘。

### 第五阶段：运营复盘与数据看板

目标：形成 SaaS 产品的持续运营能力。

交付内容：

- 推荐效果看板。
- 用户画像分布看板。
- 商品选品看板。
- 库存风险看板。
- 补货效果复盘。
- 商家维度数据隔离。

验收标准：

- 商家能够查看推荐、库存、选品效果。
- 运营能够识别问题商品和高价值用户。
- 系统能够基于数据持续优化策略。

当前落地状态：

- 已通过 `GET /api/dashboard/overview`、`recommendation-funnel`、`product-selection`、`user-profiles`、`inventory-health` 支撑推荐、画像、选品和库存看板。
- 已新增 `GET /api/dashboard/replenishment-review` 支撑补货效果复盘。
- 已新增 `GET /api/dashboard/operations-review` 汇总推荐、画像、商品、库存、补货、MCP 和工作流健康指标。
- 前端看板已在补货页和工作流页展示第五阶段运营复盘数据。
- 新增接口均按 `tenant_id` 和 `merchant_id` 过滤，保留商家维度数据隔离。

## 3. 测试与验收策略

### 单元测试

重点覆盖以下逻辑：

- 标签权重计算。
- 余弦相似度计算。
- 推荐过滤逻辑。
- 选品评分逻辑。
- 补货量计算逻辑。
- 状态流转与幂等处理逻辑。

### 接口测试

重点覆盖以下接口：

- 行为采集接口。
- 推荐接口。
- 选品评分接口。
- 库存预警接口。
- 补货建议接口。

### 集成测试

重点覆盖以下链路：

- 行为采集到用户画像更新。
- 用户画像到推荐结果生成。
- 推荐曝光到反馈日志写入。
- 订单支付到库存扣减。
- 退款或取消订单到库存回滚。
- 库存预警到补货单生成。

### 验收指标

- 推荐接口平均响应时间小于 300ms。
- 行为采集接口成功率大于 99%。
- 库存预警任务能够稳定定时执行。
- 补货单状态流转完整可追踪。
- 核心 WORKFLOW 失败后可重试。
- 关键数据链路具备幂等与重放能力。

## 4. 风险与应对

### 数据不足风险

应对方式：

- 初期采用规则推荐和热门商品兜底。
- 新用户使用渠道、分类、热门商品做冷启动。
- 新商品使用商品标签、品类热度和毛利作为初始权重。

### 算法效果不稳定

应对方式：

- 保留推荐解释字段，方便运营排查。
- 先上线可解释算法，再逐步引入复杂模型。
- 按场景配置不同推荐策略。
- 引入去重、频控和黑白名单规则。

### 库存预测不准确

应对方式：

- 初期使用近 7 天、近 30 天销量均值。
- 对爆品、季节品、长尾品使用不同预测窗口。
- 保留人工审批，避免自动补货失控。
- 补货建议同时输出清仓和观察策略。

### 模块耦合风险

应对方式：

- 所有能力通过 MCP 调度。
- SKILL 保持单一职责。
- WORKFLOW 只负责流程编排，不直接写复杂业务逻辑。
- 数据表和事件流按租户维度隔离。

## 5. 最小可行版本 MVP

### MVP 范围

- 用户行为采集。
- 用户画像生成。
- 个性化推荐。
- 推荐反馈日志。
- 库存预警。
- 补货建议。

### MVP 暂不包含

- 复杂机器学习模型。
- 多租户计费。
- 高级 BI 看板。
- 轻量 BI 看板已作为第一、二阶段测试辅助能力实现，后续可继续扩展。详细设计见 [bi_dashboard.md](bi_dashboard.md)。
- 自动采购系统对接。
- 复杂营销自动化。

### MVP 成功标准

- 用户行为能够持续沉淀。
- 推荐能够基于用户画像动态变化。
- 商品推荐效果可通过点击和购买反馈衡量。
- 库存风险能够自动发现。
- 补货建议能够被商家用于实际决策。

## 6. 后续演进方向

- 引入协同过滤、召回排序模型和深度学习推荐模型。
- 增加 A/B 测试能力，对比不同推荐策略。
- 接入外部电商平台数据，增强选品能力。
- 增加商家多租户隔离、权限和计费体系。
- 将 WORKFLOW 扩展到营销活动、用户召回和售后处理。
- 将 SKILL 沉淀为插件市场，支持按行业快速复用。
